Symbio™ 700 - When Restoring From Backup Retain the Destinations Device’s Communication Setting and Unit Tag Information Is Not an Option.

General Symbio 700Communications / BACnetManuals / Literature
Section: Troubleshooting  •  Category: Light Commercial Rooftops | Splits
Created: 2025-02-06  •  Last updated: 2025-02-12

 

 

Issue:

When using a backup of a Symbio 700 controller to restore to a device it is not possible to select  Retain the destinations device's communication setting and unit tag Information.

 

Most Trane Controllers have this feature built into them that allows the controller to save this data and then restore this data back to the controller after the backup is restored.  This is not a function of Tracer TU but a function of the Controller.

 

 

The Symbio 700 does not have this feature and thus a backup should not be restored when remotely connected to the controller.  Restoring the backup to the controller will cause the communication parameters from the copied device to be used by the controller and communications with the device may not be possible after a remote restore is done.

 

It is recommend to only restore a backup on site when plugged in directly to the Symbio 700.  Before restoring it is also recommend to copy the device communication settings (protocol settings) prior to restoring a backup so that they can manually be put back after a restore.

 

This was a design decision for this unit.
